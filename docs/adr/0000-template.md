# ADR-0000 — Short decision title

- **Status:** Proposed / Accepted / Superseded
- **Date:** YYYY-MM-DD
- **Owner:** Named responsible role
- **Related issue/PR:** URL(s)

## Context
What verified source facts and constraints drive this decision? Distinguish existing runtime behavior from proposed work.

## Decision
What exactly will be adopted? State boundaries and source of authority. Never mark `Accepted` without the decision-maker's approval.

## Alternatives
Consider at least the current design and viable alternatives; compare operational, privacy, cost and rollback effects.

## Security / KVKK / data migration
List data classification, tenant segregation, secret handling, migration compatibility, and rollback risks.

## Validation and release gates
Define unit/API/e2e/negative tests, staging evidence, read-back, dependency issue and any owner/club sign-off.

## Consequences
Expected benefits, trade-offs, technical debt, unknowns, and date for re-review.
